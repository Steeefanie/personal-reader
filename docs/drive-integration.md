# 可选云盘接口接入说明

## 独立性与兼容范围

阅读器可独立构建、运行和测试，本地阅读不需要云盘服务。云盘是可选 HTTP 客户端能力，用户输入兼容服务的 HTTPS 根地址后才进行设备绑定、书库下载和阅读状态同步。仓库不包含服务端源码、用户管理页面、服务端数据库或部署配置。

兼容服务仅需实现 [drive-contract-v1.md](drive-contract-v1.md) 的请求与响应，不要求特定服务端框架、物理目录或相邻工程。`DriveTransport` 可注入模拟响应，便于在没有服务端和真实凭证的情况下验证客户端。

当前 Room 数据库为 v5（包含账号隔离的删除标记和逐书仅本地设置）；同步始终为每本书一份 JSON，路径 `/api/reader/v1/progress/:bookHash`，每份至多一条阅读进度及该书书签，不汇总其他书籍。真实 HTTPS、服务端授权页面和实际设备仍需对具体服务分别联调；服务兼容性以实际联调结果为准。历史修复说明见 [sync-fixes-v0.3.1.md](history/sync-fixes-v0.3.1.md)。

## 接口与模块

| 模块 | 行为 |
| --- | --- |
| `DriveClient` / `DriveTransport` | 固定 `/api/reader/v1` 前缀、HTTPS 根地址校验、Bearer 请求头、响应校验，不跟随重定向 |
| `SecureCredentials` | Android Keystore AES-GCM；私有配置只保存密文，用连接 ID 作为附加认证数据 |
| `DriveService` | 连接和用户选择、身份验证、绑定撤销、完整目录分页、完整进度索引、前台同步调度 |
| `BookDownloader` / `DownloadBody` | 元数据校验、临时分段、Range/If-Range、200/206/416、长度和版本检查、完整 SHA-256 校验 |
| `ProgressSync` / `StateMerge` | 单书互斥、三方比较、冲突副本、ETag 条件写入、上传期间新修改保护、412 与不确定结果重读 |
| `DriveActivity` | 分类目录、下载和同步入口 |
| `DriveConnectionActivity` | 设备绑定、授权状态、最近同步和解绑 |

调用范围：

```text
POST   /bindings
POST   /bindings/poll
GET    /me
DELETE /me/device
GET    /entries?parent_id=...&limit=100&cursor=...
GET    /files/:fileId
GET    /files/:fileId/content
GET    /progress?limit=100&cursor=...
GET    /progress/:bookHash
PUT    /progress/:bookHash
GET    /books?limit=200&cursor=...   # 可选 book-list-v1
POST   /books                       # 可选 book-upload-v1 + books:write
DELETE /books/:bookHash[?file_id=...]  # 可选 book-delete-v1，另需 books:delete
```

下载以文件元数据和 GET 响应为准，不依赖 HEAD；服务端仍应按契约实现 HEAD。客户端不访问公开分享下载接口，不调用管理员资源接口。接受的角色只有 `admin`、`user`，两者均要求三项基础权限；上传和删除另需独立授权，管理角色不产生跨用户读取能力。

## 账号与数据隔离

`drive_connections` 保存连接 ID、规范化服务地址、用户 ID、设备 ID 等展示信息；凭证不进入数据库。相同服务地址和用户重新绑定时复用连接 ID，用新凭证替换旧凭证，保留原账号的待同步记录。

`book_access` 保存账号空间到内容缓存的可见映射。实际电子书以 SHA-256 复用缓存；从一个空间移除不会删除仍被其他空间引用的内容。原来的 `progress`、`bookmarks` 表继续用于未绑定的本地模式。

云端状态保存在 `cloud_states`，主键为连接 ID、用户 ID 组成的空间及 `bookHash`，包含当前完整 JSON、基准 JSON、ETag、本地修改序号、待同步标记、最近成功时间、错误及下次重试时间。`cloud_conflicts` 保存同时间进度冲突的本地副本；`remote_entries` 保存分类快照和云端删除标记。

绑定成功后，未归属账号的本地书库和阅读记录复制到当前账号空间，原本地数据保留；其他账号的数据不转交。阅读页面打开时固定所属空间，保存进度及书签时也使用该空间。逐本仅本地状态存于 `local_only_books`，不跨账号转交。手动 JSON 导入导出仅处理当前选择的空间，不在导出文件中夹带凭证或连接信息。

## 同步与失败处理

- 进度 JSON 仍为 schemaVersion 1，每本书独立一个云端文档，只允许零或一条进度，所有记录哈希必须与 URL 相同。云端与内部快照使用紧凑 JSON，最终 UTF-8 字节数限制为 8 MiB；备份美化后超限会回退到紧凑格式。
- 同步前读取最新远端和 ETag，只有 `404 progress_not_found` 视为不存在。网络错误、无权限、无效 JSON 和缺少 ETag 均不视为空数据。
- 三方合并先判断哪些记录变化；仅在两端修改同一记录时按更新时间裁决。不同 ID 的书签保留，删除标记不清理，不按百分比大小决定新旧。
- 进度同时间且不同内容时采用远端并将本地整份单书状态保存为冲突副本。书签同时间以删除优先。自动同步及重试不修改记录时间。
- 首次上传用 `If-None-Match: *`；更新用完整的 `If-Match` ETag。上传成功后才更新基准；期间若本地修改序号变化，再合并新修改并保留待同步标记。
- 412 和上传 I/O 不确定结果最多立即重读、合并三次，之后保留记录供后续重试。429 遵守 `Retry-After`，当前连接的退避时间持久化；403、413、422、428 保留数据并显示错误。
- 401 标记凭证失效、清除本机凭证，停止该设备的后续请求，但不删除离线书籍和队列。503 和一般网络错误不清除凭证。
- 全量同步发出第一个请求前，按连接持久化待办；失败后遵守 Retry-After 和退避，前台周期任务继续拉取。重新读取索引时通过已保存 ETag 跳过成功条目，账号切换不转交旧待办；进程和数据库重建后可继续。
- 目录必须完整分页后才更新本地快照；游标失效可重新从第一页获取一次，中途失败保留旧列表。进度索引包括未下载书籍，完整读取后再按版本同步。
- 前台启动和网络恢复校验 `/me`，用户和设备 ID 必须与绑定记录一致。阅读页激活时暂停周期待办处理；退出阅读尝试同步，非阅读状态的前台约每 30 秒处理待同步记录。后台停止周期循环，不增加常驻服务；系统结束进程后在下次启动继续处理队列。
- 网络请求有连接和读取超时。下载取消在协程取消检查或读取超时处退出，合法分段用于续传。设备撤销时中止活跃传输仍须由服务端按契约执行。

## 单书删除扩展

书库菜单与云盘长按菜单按书籍状态提供“仅移除本地副本”“仅移除云端副本”“从本地和云端删除”，确认面板复用无阴影的底部面板；底部操作靠右，面板最上沿全宽，内部横线按统一 20dp 留白。

删除前重新校验身份、能力及独立授权，一次只删除一个书籍文件和一个 JSON。收到完整成功回执后才移除本机副本；超时、未授权、接口缺失或部分回执保留本机副本。删除与单书同步共用互斥锁，成功后持久化 `deleted_cloud_books` 标记；收到服务端 `410 book_deleted` 同样停止该书回传，其他设备的本地历史可离线保留。捕获的账号不因切换而改变，其他空间仍引用的内容缓存继续保留。

服务端需实现原子删除、幂等回执、索引删除标记及拒绝旧进度 PUT。客户端实现和模拟接口通过不表示具体服务已兼容。完整请求、回执和联调要求见 [cloud-book-deletion.md](cloud-book-deletion.md)。

## 真实联调顺序

1. 使用兼容服务提供的 `/bindings`、`/bindings/poll`、手机授权页及 `/me`，在真实 HTTPS 环境确认角色、scope、用户和设备归属。
2. 阅读器输入实际 HTTPS 根地址；扫码核对绑定码，验证一次性领取与设备备注。授权 URL 必须属于同一网盘，不能包含临时 `device_code`。
3. 核对获授权的书库根目录、分类分页、文件元数据和哈希，验证实际 EPUB/PDF 下载、重命名、分类移动及中断续传。
4. 使用契约约定的进度索引及单书 GET/PUT，用两台真实设备验证冲突、离线书签删除、上传期间继续阅读和新设备恢复。
5. 验证服务器设备撤销、活跃下载中止、账号隔离、流量预算和限流，以及文石 Leaf5+ 的网络恢复、休眠与耗电。

模拟接口结果不代替具体服务和真实设备联调。Android 客户端要求受系统信任的 HTTPS 根地址，不支持 HTTP，也不关闭 TLS 校验；授权 URL 必须与用户输入的根地址同源。

## 安全与兼容边界

绑定用的临时设备码只在当前页面协程内存中使用，取消、过期和页面销毁时停止轮询；二维码只编码服务端提供的同源验证 URL。没有绕过 TLS 校验的代码，不添加自签名证书信任或全局信任管理器。长期凭证不交给正文渲染层或文件浏览链接。

电子书缓存本身未加密，设备撤销不等于远程擦除离线内容。凭证依赖当前 Android Keystore；系统密钥失效时需要重新绑定，阅读数据不删除。禁用应用云备份及设备迁移备份，手动 JSON 仍可用于用户主动备份。设备时间偏差仍会影响同时修改时的时间裁决。

二维码使用 Project Nayuki Java 编码器的四个源码文件，固定上游提交并保留 MIT 许可，未增加远程 Maven 依赖。参考：[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[二维码编码器](https://github.com/nayuki/QR-Code-generator)。

完整书籍列表与上传协议见 [cloud-library-sync.md](cloud-library-sync.md)。1.0.0 的验证结果见 [VALIDATION.md](../VALIDATION.md)。
