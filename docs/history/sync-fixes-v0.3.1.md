# 0.3.1 同步修复（历史）

本文仅记录 0.3.1 的客户端实现。每个账号、每个 bookHash 对应一份进度 JSON，通过 `/api/reader/v1/progress/:bookHash` 访问；服务端物理文件路径不属于接口约定。当前实现和验证范围见 [接入说明](../drive-integration.md)及 [VALIDATION.md](../../VALIDATION.md)。

## 修复

1. 云端与内部快照使用紧凑 JSON，写入前按最终 UTF-8 字节数限制为 8 MiB。手动导出的美化版本超限时回退紧凑格式。旧缩进记录在有界条件下压缩、校验，成功同步后重写，不删除进度或书签。
2. 通过事务内 SQL substr 分块读取云端状态与冲突 JSON，按 Unicode 码点推进，避免 CursorWindow 大小限制和表情字符截断。统计状态时不读取完整 JSON。
3. 完整同步在第一个请求前持久化待办，异常、Retry-After 和退避均保留。到期扫描索引，以 ETag 跳过成功项；账号切换不转交待办。
4. 同 ID、同时间且删除状态相同的不同书签内容采用远端，并保存本地冲突副本；删除标记优先，手动导入同时间保留本地。

## 历史验证

- 36 项 JVM 测试、31 项 Android 11 模拟器检查通过，包含 EPUB/PDF 回归。
- 使用单书 23,000 条人造书签验证大文档读写、Flow 观察、冲突副本和 Unicode 跨块完整性。
- 同一份 6,290,937 字节的测试 JSON 经修复后的序列化保持字节数并可重新读取；旧格式曾膨胀至 8,682,953 字节而超过限制。该边界样例不代表常规书签记录大小。
- 262 份独立远端进度模拟第 224 次读取返回 429 / Retry-After:60；关闭并重建服务、数据库后，退避期间不请求，到期仅读取剩余 39 份，已完成的 223 份不重拉，不发 PUT。
- 索引首次读取失败保留待办，切换账号不处理上一账号队列，切回后可恢复。

测试采用模拟传输和可控时钟，未验证正式 HTTPS、手机授权或真实设备联调。该版本 versionCode 为 4，最低 API 24，Room v3，ARM64 包沿用既有签名。
